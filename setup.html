GATHERIDE CREATIONS LLP / Certificate Operations
ONE-TIME DEPLOYMENT GUIDE · VERSION 1.0

Publish your certificate system safely.

This project has two parts: a branded GitHub Pages entry website, and a restricted Google Apps Script backend for identity approval, duplicate checks, certificate issuance, printing and Google Sheets storage.

Security first: Do not deploy the Apps Script web app as “Anyone” or “Anyone with a Google Account” when it executes as you. Choose “Only myself” for the initial administrator-only version. Do not publish the Google Sheet or include actual PAN/DPIN values in GitHub.
STEP 01 / CREATE THE BACKEND

Open Google Apps Script

  1. Sign in to the Google account that will own the certificate register.
  2. Visit script.google.com and create a new project.
  3. Name it GATHERIDE Certificate Issuance.
  4. Replace the generated Code.gs file with the full contents of appsscript/Code.gs supplied in this ZIP.
  5. In Apps Script select + → HTML, name the file exactly Certificate, and paste the contents of appsscript/Certificate.html.
STEP 02 / INITIALIZE THE GOOGLE SHEET

Run the one-time setup

  1. Choose function setup from the dropdown in Apps Script and click Run.
  2. Grant the Google authorization prompts for the account that owns the sheet.
  3. Open Execution log; it prints a link starting REGISTER URL:.
  4. Open that Google Sheet. It includes Certificates, Verified_Partners and Audit_Log.
  5. Restrict Sheet sharing to designated authorized administrators.
STEP 03 / APPROVE IDENTITIES

Prepare the verification register

In the private Verified_Partners tab, enter the person/entity from their validated paperwork. Never preapprove guessed details.

Registered Name | exact legal name ID Type | PAN or DPIN DPIN / PAN | exact identifier as text Status | APPROVED Verified By | reviewer / approver Verified On | review date Evidence Ref | document / LLP agreement ref

All three of status, reviewer and evidence reference are required. Back-end validation checks the name, ID type and identifier against the approved row.

STEP 04 / DEPLOY THE PRIVATE CONSOLE

Publish the Apps Script web app

  1. Apps Script → Deploy → New deployment.
  2. Deployment type: Web app.
  3. Execute as: Me.
  4. Who has access: Only myself.
  5. Click Deploy and copy the web app's https://script.google.com/macros/s/.../exec URL.
  6. Open the URL while signed in as the owner. The certificate form should display portfolio 0006 on a new register.
STEP 05 / PUBLISH GITHUB PAGES

Upload the ZIP contents

  1. Extract the ZIP locally. Create a new GitHub repository, such as gatheride-certificates.
  2. Upload index.html, styles.css, script.js, config.js, setup.html, and the assets folder at the repository root.
  3. In config.js, paste the Apps Script /exec URL inside appScriptWebAppUrl: '...'.
  4. Commit changes to main. Open Settings → Pages → Deploy from a branch → main → /(root).
  5. GitHub gives you a live entry URL. The button on the landing page opens the restricted console.
STEP 06 / TEST WITHOUT ISSUING BLINDLY

Verify the controls

  1. Run runValidationSelfTest in the Apps Script editor (no certificates are issued).
  2. Test an incorrect DPIN/PAN format — it should be rejected.
  3. Test a correct-format ID not on the approved register — it should be rejected.
  4. Once you have a real approved partner, issue a legitimate certificate and confirm the new row appears in the private Certificates sheet.
  5. Retry the same certificate number and identity: both should be blocked. Use Find existing certificate to reprint for copies.
Important legal limitation: This system verifies input format and checks a human-approved register. It does not connect to the Income Tax Department or MCA and cannot automatically prove that a PAN or DPIN is actually allotted, active or belongs to a person. The approver must inspect authoritative documentation and confirm formal LLP partner admission before marking a record APPROVED. No certificate represents a guaranteed return or proof of payment.
